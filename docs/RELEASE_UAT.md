# Staging acceptance script

Use the tagged production build on restricted staging. Create two named synthetic administrators and fake employees A, B and C with separate accounts. Confirm the business timezone is Asia/Manila. Use private delivery for temporary passwords and real phones for QR enrollment and TOTP. Record the test date, release revision, expected and actual outcome, pass/fail, tester and sanitized evidence for each row. Resolve failures and rerun before sign-off. [Blueprint §15](BLUEPRINT.md#15-mandatory-acceptance-test-scenarios)

Configure a synthetic project with Task X and Task Y, an eight-hour schedule, fake PAY settings, a REGULAR earning type, no deductions and exact test rates. For example, verify a daily rate of PHP 800.00 for one approved eight-hour day and an hourly rate of PHP 125.50 for six approved hours, which yields PHP 753.00. Write down the staged cutoff and payday and approve payroll after the cutoff. Use actual punches in the real staging walkthrough. Use the isolated test clock procedure for dates impractical to schedule. Never change the VPS clock or use the test clock in shared staging or production.

| §15 | Steps | Expected evidence |
| --- | --- | --- |
| 15.1 | Grant A duty. Leave B unactivated. Sign in as both. Clock In as A after duty login. | A's explicit punch creates a shift. Login alone creates no time. B cannot open duty tools or Clock In. |
| 15.2 | Enroll TOTP on real phones. Use wrong passwords and TOTP codes, enable PIN on staging and test bad PIN, and reuse one accepted TOTP. Wait through a lockout. Exercise a recovery code and an administrator-assisted reset with verification. | Failed factors remain generic, attempts lock out and reuse fails. Recovery produces setup-only access until enrollment. Reset revokes old sessions and is audited. Return staging PIN to its intended setting. |
| 15.3 | Start a shift and timer as A, then revoke duty as administrator. Retry using A's original browser session. | Next request loses duty access. Legitimate time and audit history remain, with system closure flagged as applicable. |
| 15.4 | Assign one shared task to A, B and C. Time and submit separate contributions, then review each. | Three distinct contributions and timers feed one shared task count. Peers cannot view one another's submissions. |
| 15.5 | Start X, pause it, switch to Y, and return to X on another date. Check administrator and own records. | Pauses and idle gaps are excluded. Intervals do not overlap and sums match recorded server timestamps. |
| 15.6 | Clock Out with a running task, then repeat with a paused timer on a separate shift. | Shift, break if any and timer close at the server instant. Audit shows the reason and stale Resume fails. |
| 15.7 | Record eight hours of attendance and six hours of task time. Open daily and weekly reports and export. | Separate totals and a two-hour review gap. There is no automatic pay deduction. |
| 15.8 | Prepare payroll for the different rates above, approve it, then change one effective rate. | Both expected PHP amounts reconcile. The frozen amount, rate evidence, digest and issued PDF stay intact. |
| 15.9 | Resolve a missed punch with reason, approve attendance, and recalculate a draft. Exercise void or replacement on an unpaid approval and a later-period adjustment on a paid line. | Original punches, reviewer reason and before/after evidence remain. Paid history, payment and PDFs retain their original values. |
| 15.10 | Upload an allowed attachment and test guessed work file URLs. Download A's own finalized PDF while off duty. Try its reference, a guessed ID and work file routes as B and anonymously. Repeat on mobile. | Only authorized access succeeds. Foreign and missing protected API IDs produce indistinguishable responses. Attachment has no-store and nosniff. |
| 15.11 | Approve without paying. Record a fake payment with recent MFA and retry. Download original and paid versions. Try a duplicate normalized reference on another line. | Approval leaves payment empty. Exactly one payment is recorded. Historical Approved PDF remains byte-identical, Paid PDF shows actual date, and duplicate reference fails. |
| 15.12 | Exercise authorized overnight work, Manila midnight, weekend cutoff and year rollover, missing punches, bad MFA, oversized/malformed uploads and mobile sessions. Use a dedicated disposable staging replica for controlled dates and destroy it after testing. | Time is attributed to the proper date and window. Exact totals and review flags survive boundary cases. Invalid MFA/uploads fail and responsive screens work on the target phones. |
